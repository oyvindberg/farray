  <code>IArray(1, 2, 3)</code> is one array allocation, and an FArray is that array <em>plus</em> its

## FArray(…) is a macro, and that matters

`FArray(a, b, c)` looks like the varargs constructor every library has. It used to be what every
library has — a wall of 32 arity overloads generated to dodge the varargs `Seq` — until one inline
macro replaced the wall: it reads the literal arity off the syntax tree and emits the exact
construction for what you wrote — `Empty`, `One(a)`, or a typed leaf array filled in place. No
`Seq[A]` wrapper, no boxing of the elements on the way in, per call site.

The consequence shows where generic varargs hurt most — a method that constructs collections of
*several element kinds*. A shared generic varargs path sees `Int`, `Long`, `Double`, `String` flow
through one call site and boxes them all; the macro emits four independent typed constructions, so
there's no shared site to poison:

## tabulate, and the typed-array trick

`tabulate(n)(f)` is the workhorse constructor, and it carries a measured story: reference FArrays
are normally backed by `Object[]`, which makes a later `toArray[String]` a *checked* per-element
copy — that measured at 0.15× once. So `tabulate` summons a `ClassTag` **opportunistically**: when
one is available for the element type, the backing array is allocated as the real `String[]`
(`Trade[]`, …), and `toArray` becomes a raw `arraycopy` — 6.7×, tying the raw array. When no tag is
in scope, nothing is demanded of the caller; you just keep the `Object[]` backing.

`fill(n)(elem)`, `iterate(start, n)(f)` and `unfold(seed)(f)` are the same machinery with different
element sources; `from`/`fromArray`/`fromIterable` copy once into a leaf (an `Array` input is
wrapped kind-exactly), and `fromBoxedArray` is the escape hatch for an `Array[Object]` you got from
reflective code.

## range is not a loop

`FArray.range(0, n)` allocates nothing per element — it's a lazy `RangeNode`, the arithmetic
sequence *as a tree leaf*. Reads compute `start + i * step`; the range only becomes a real array if
something forces it. A pipeline that maps over a range never pays for the range:

## Getting back out

The exits are as boring as they should be, which is the point: `toArray` on a typed backing is an
`arraycopy` (0.97× of raw — the copy is the whole cost for everyone); `copyToArray` and `indices`
tie; `mkString` runs ~1.3× ahead on a tuned append loop. `toSeq` is O(1) — a zero-copy `FArraySeq`
wrapper — which is deliberately *not* benchmarked against native Seqs returning `this`, an
un-winnable one-allocation gap the suite documents rather than games.
