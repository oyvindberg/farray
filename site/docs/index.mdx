## Ten years of waiting for the JVM

<p className="lede">
  Scala collections are a joy to write — and box every primitive. The <code>while</code> loop that
  doesn't box is a joy to nobody. I spent a decade waiting for the something in between:
  specialization, miniboxing, Valhalla's <code>List&lt;int&gt;</code>. It never shipped. The verdict,
  every release: if it has to be fast, write it in Java.
</p>

In 2023 spite produced a prototype: the whole `IndexedSeq` API as `inline` `while` loops over one
flat `Array[AnyRef]`. It beat the collection library — but it boxed, and unboxing wasn't a bolt-on.
It wanted per-kind storage, a core the inliner couldn't defeat, machinery to keep a user's lambda
unboxed across a library boundary: years of evenings I didn't have. The repo slept for three years.

## And then — boom

June 2026, with Claude doing the heavy lifting: twelve days, three hundred commits, and a decade of
roadmap stopped being sequential —

At 100k elements: **36× the fastest competitor**, **83× List** — and **15× the same pipeline run
eagerly on FArray itself**.

Why it runs away: eager stages each allocate a collection whose only purpose is to be thrown away by
the next. `.fuse` builds none of them:

<FusionDiagram />

It's a macro. At compile time the whole chain becomes one `while` loop — the intermediates, the
`Function1`s, the boxing: gone. Not a claim to take on faith: the lowering is a golden test in the
repo, and this is what those fourteen stages compiled to.

## Three speeds

One number proves too little, so calibrate it. Fast JVM code was never the hard part — anyone can
mutate an `int[]` in a `while` loop. The hard part is that speed from **immutable,
expression-oriented code**, where erasure boxes, inlining gives out, and every stage materializes a
collection that lives for one line. The chart is really three speeds:

<Ladder />

**Today's speed.** `List` and `Vector` pay a box, an allocation and a dispatch — per element, per
stage. The Chunks put arrays under the boxes; `IArray` drops the boxes but still copies at all
thirteen seams. The intermediates are real; escape analysis will not save you.

**The type swap.** Same code, `FArray` under it. Storage is a genuine `int[]`, structural steps are
O(1) nodes instead of copies, and every lambda-taking op is `inline` — the unboxing lives in the
method signature, so it can't collapse back to boxing as the surrounding method grows, which is
exactly where the rivals' single-op ties give out. No fusion yet, and it already clears the field:
[the next page](./chains.mdx) scores every chained benchmark in the suite, live.

**The word.** Views, iterators and LazyList promised chain-collapsing and delivered interpreter
overhead; `.fuse` deletes the thirteen intermediates at compile time. The ceiling is the
hand-written loop — because that's what `.fuse` emits.

Live on the type swap; spend the word where it matters. The rest of the site is the climb.
